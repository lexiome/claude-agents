# Minimalist check

The rule: spend the minimum, and only when it unlocks the next step. Answer each line in one short sentence.

| Question | Answer |
|---|---|
| Did a real user ask for this, or did they get stuck without it? | |
| Can it be done by hand first, before we build it? | |
| What is the smallest version we can ship this week? | |
| Does it cost time or money? Can time replace the money? | |
| Can we undo it if it fails? | |
| Does it move your kill metrics or revenue? | |
| Does it stay inside your product's safety line (e.g. filing clerk, not a doctor)? | |

**Verdict:** do it / simplify it / not now, plus the minimal version in two or three lines.

## Pricing (only when a price is on the table)
- Example model: the basics are free, a few uses a month are free, and deeper features are paid, like paying for phone storage.
- Charge something for the paid tier. Free and $1 behave very differently.
- Start low. Prices can go up as the product improves.
- Price by value to the family, not by our server cost. Also check that the price covers our per-user cost (model calls, push, hosting) from your cost doc.
- Do the maths: how many paying families cover the monthly costs, and later a founder salary? At a realistic signup rate, how long does that take?
- Decide who is always free (e.g. read-only viewers).
- Route the numbers to @cfo and the decision to the founder.
